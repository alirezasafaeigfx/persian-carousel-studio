## 4. Promoted strategy rules

### Rule A — design for ordinary people first

Public-facing language must be understandable without technical knowledge.

Prefer:

- «با گوشیت رایگان بساز»
- «برای ساخت لوگو پول نده»
- «رایگان استفاده کن»

Avoid leading with:

- SVG
- API
- watermark
- model names/specifications
- technical implementation detail

Technical detail belongs in the caption only when it materially helps the user.

### Rule B — broad pain before tool name

The strongest Reel topics start from a broad user problem, not from the existence of a tool.

Priority pain classes:

1. saving money;
2. getting something useful for free;
3. making a common task easier on a phone;
4. tools usable by ordinary users and small businesses;
5. practical access for Iranian users.

### Rule C — Iranian usability gate before production

A candidate tool must be tested before spending Flow credits.

Minimum gate:

- real free tier or truly usable free access;
- no hidden mandatory foreign payment;
- no required Meta dependency when Iranian access is materially restricted;
- usable from Iran, with VPN requirement disclosed when relevant;
- mobile-friendly enough for ordinary users;
- Persian support when the concept depends on Persian;
- real export/output, not a demo-only experience;
- output quality good enough to recommend publicly;
- claim verified before publication.

A tool that is technically free but produces poor output is a FAIL.

### Rule D — combine the two best mechanisms

Target for future high-upside Reels:

`Copilot-style hook strength + Logo/ChatOn-style concrete utility`

Internal target profile:

- Reel view rate > 50% preferred;
- strong share/save behavior;
- simple one-word CTA only after payoff;
- broad non-technical promise;
- 8–10 seconds when possible;
- one continuous creator-native Flow render when talking-head is used.

## 5. Operating workflow from now on

```text
Broad Iranian pain / need
-> candidate tool research
-> Iranian usability gate
-> hands-on user test
-> Direction Approval
-> Script Approval
-> Flow render
-> Video QA
-> Cover / edit assets
-> Publish
-> Metricool observation
-> native Instagram retention screenshot only if needed
-> human-readable Notion report
-> promote only evidence-backed learnings
```

Do not move to Flow before the tool passes the usability gate.

## 6. Reporting cadence

A weekly ASDEV analytics review is now part of the operating system.

Each weekly review should compare:

- latest 7 days vs previous 7 days;
- best/worst Reels;
- views and reach;
- shares and saves;
- comments;
- average watch time;
- Reel view rate;
- follower movement;
- repeated hook/topic/CTA patterns.

Human-readable findings belong in the Notion `Viral Reels Lab` area.

GitHub should retain only durable rules, benchmarks, and promoted learnings—not every daily fluctuation.

---

## 7. Current strategic conclusion

The account does not need more random experimentation.

The current job is to repeatedly search for **real, useful, accessible tools tied to broad Iranian pain points**, then present them with the proven short-form structure:

`simple pain -> immediate free benefit -> one concrete outcome -> one CTA`

Primary growth benchmark remains Copilot for hook/follow behavior, while practical utility Reels provide the best path to stronger sharing and saving.
