## P-NBLM-002 — Reference Image Policy Failure → Prompt-Defined Character

**Status:** `APPROVED-PATTERN`

Initial production attempted to use an uploaded AI-generated portrait as the visual reference.

Flow returned a policy-related generation failure.

A long defensive prompt explaining that the portrait was fictional did not solve the practical problem.

Successful production decision:

```text
There is NO reference image.

Create an ORIGINAL FICTIONAL AI-GENERATED CHARACTER from the description below.
```

### Rule

When the exact identity is not strategically important and an uploaded portrait triggers Flow's person-image policy:

`remove the portrait reference → describe a fresh fictional character in the prompt`

Do not waste credits repeatedly retrying the same nonessential image reference.

## P-NBLM-003 — Truthful Income Hook Pattern

**Status:** `WORKFLOW-APPROVED`

The hook can be aggressive without promising impossible results.

Reusable structure:

```text
INCOME DESIRE
→ one concrete deliverable/service
→ one CTA
```

Truthfulness contract:

```text
Do not claim:
- guaranteed income
- passive automatic income
- the AI platform pays the user
- unlimited free access unless verified

Frame income as:
AI-assisted production of a service that can be offered to customers.
```

This preserves a broad public hook while keeping the underlying claim defensible.

**Status:** `WORKFLOW-APPROVED`


The successful revision reduced the message hierarchy to:

